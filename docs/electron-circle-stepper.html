Reading 6502 assembly

Each line of the listing is one instruction: a three-letter name (the mnemonic) and usually one operand that says what to work on. The assembler turns each line into 1 to 3 bytes of machine code, shown in the second column. The 6502 then runs them one at a time, from the address in its program counter (PC).

Registers

A (the accumulator) is where arithmetic happens. X and Y are mostly used as counters and table indexes. Each holds one byte, 0–255. PC is the address of the next instruction, and S points into the stack at &0100–&01FF.

Flags

Instructions set flags that later ones test. C (carry) catches the ninth bit of an addition, or says "no borrow" after a subtraction. Z is set when a result is zero, and N copies bit 7, which is the sign in two's complement. Branches such as BMI and BCC jump or not depending on a flag.

Zero page

Addresses &00–&FF are "zero page". Instructions that use them are one byte shorter and one cycle faster. The Advanced User Guide says "BASIC reserves locations &70–&8F for the user", so the program keeps all its variables there.

Numbers bigger than a byte

The 6502 only adds 8 bits at a time. A 16-bit number such as D is kept as two bytes: d (low) and d+1 (high). The low bytes are added first, and the carry flag passes any overflow on to the high byte. Negative numbers use two's complement: &FF is −1, and bit 7 set means negative.

How MODE 4 lays out the screen

MODE 4 shows 320 × 256 pixels in 2 colours, from &5800 to &7FFF (Advanced User Guide, Appendix C). Each byte holds 8 pixels side by side, one bit each, with bit 7 as the leftmost pixel. The bytes are not stored a whole line at a time. They follow the 8 × 8 character cells: 8 bytes go down one cell, then the next 8 bytes are the cell to its right. One row of 40 cells takes 320 bytes, so the next character row starts 320 bytes later.

So for pixel column px and row py (counting down from the top):

address = &5800 + (py DIV 8)*320 + (py MOD 8) + (px DIV 8)*8
bit     = &80 >> (px MOD 8)

Multiplying is slow on a 6502, so BASIC works these out in advance. rowlo/rowhi hold the address of each of the 256 pixel rows, and rlo/rhi/rmask and llo/lhi/lmask hold the byte offset and bit for the columns to the right and left of the centre. The machine code only adds two table entries together, which is what the address builder above shows.

The algorithm

The program draws one eighth of the circle, from the top (x = 0, y = r) round to the 45° diagonal, and mirrors each point into the other 7 eighths. In that eighth, each step moves one pixel to the right. The only question is whether y stays the same or goes down by one.

D answers that question. It tracks, in whole numbers, whether the point halfway between the two candidate pixels is inside or outside the true circle. If D is negative the midpoint is inside, so the pixel straight across is closer. D then grows by 2x + 3. Otherwise the diagonal pixel is closer: y goes down and D changes by 2x + 5 − 2y. That is the textbook Bresenham update d = 3 − 2r, halved (D = (d − 1)/2), so that every step fits in a byte.

With radius 127 the loop runs 91 times and makes 728 pixel writes, which light 720 different pixels: at x = 0 and on the diagonal, two of the 8 symmetric points are the same pixel. Run the stepper with a small radius, such as 8, to follow every decision.

The whole BASIC program (circle_asm_mode4.bas)

BASIC sets up MODE 4, builds the lookup tables, assembles the code with BBC BASIC's built-in assembler, then runs it with CALL circle. On Electroniq, drawing a radius 127 circle takes a TIME of 5 (50 ms). The stepper counts 41,625 cycles for the same circle, which would be about 21 ms at a steady 2 MHz. The difference is the Electron's RAM: the CPU drops to 1 MHz whenever it reads or writes RAM, and here the code, tables, variables and screen are all in RAM. The stepper counts cycles as if at 2 MHz and does not model that slowdown.
